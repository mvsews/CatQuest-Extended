# Написать команде из игры

Правый клик по иконке CatQuest у миникарты → **Написать нам**. Альтернативная
команда: `/cqcontact`. Старые пункты закрепления и настроек остаются в меню.

Форма содержит категории **Ошибка**, **Предложение**, **Другое** и большое
многострочное поле с прокруткой. Enter добавляет строку; сообщение отправляется
только кнопкой «Отправить». Закрытие сохраняет черновик в SavedVariables аддона.
Обычное закрытие игры сохраняет их; браузерный F5 не гарантирует запись ещё
не сохранённых игровых переменных.

Ограничение текста — 4000 байт UTF-8 (около 2000 русских букв). В форме можно
включить флажок **Приложить диагностику аддона и расширения**: тогда к обращению
добавятся текущий журнал CatQuest и журнал браузерного расширения. Флажок выключен
по умолчанию; при включении текст обращения ограничен 2000 байтами, чтобы оставить
место для диагностики. Текст передаётся
тихими маркерами, поэтому длинное сообщение может передаваться несколько минут.
В окне виден прогресс, можно закрыть форму и продолжать играть. Игру и страницу
следует оставить открытыми до завершения передачи.

Такая же галочка есть в окне «Что не так с озвучкой?». Обычная жалоба отправляется
в таблицу `feedback` как раньше, а при включённой галочке дополнительно создаётся
обращение с контекстом жалобы и обоими диагностическими журналами.

Клиент кэширует прочитанные пути, поэтому отдельный пул из 80 кадров не
переиспользуется до перезагрузки страницы. Это суммарно около 4640 байт текста за
загрузку игры. Если новый текст не помещается в оставшийся пул, отправка не
начинается и черновик остаётся в форме; сообщение предлагает обновление/F5.

Для исправленной доставки и атрибуции нужны аддон **0.10.68** и расширение **0.6.39**. Отправка работает независимо от
включения серверной озвучки и статистики; в обычном локальном клиенте без
браузерного расширения HTTP-транспорта нет, форма сохраняет текст при отказе.

## Доставка

- Отдельные файлы `contact/<slot>/<position>/<nibble>.ogg`, кадр типа 7.
  Кадр содержит ID сообщения из 8 байт, индекс/число частей, категорию, до 58 байт
  исходного текста и контрольную сумму. UTF-8 декодируется после сборки всех частей.
  Кадры обрабатываются сразу при чтении, без таймера в игровом worker: во время
  выполнения игры его event loop может не исполнять отложенные callbacks.
  Заголовок `CQ2` содержит время нажатия, версию аддона и исходного персонажа;
  для сообщения с диагностикой используется `CQ3`. Расширение отдельно сохраняет
  `addon_diagnostics` и формирует `extension_diagnostics` из журнала service worker.
  Общий пакет ограничен 4500 байтами, текст пользователя — 4000 (или 2000 с диагностикой). Заголовок
  и расширенный контекст отправляются только расширению, объявившему поддержку `contactContext`.
- Расширение сохраняет каждую часть в `contactParts` и собирает полный текст в
  `contactOutbox`. Перезапуск service worker между частями не теряет уже принятые
  данные. Незавершённые записи хранятся до 7 дней.
- Полностью полученные сообщения подтверждаются через `contactReceived` в
  `Bridge.lua` при следующей загрузке. Неподтверждённые игровые сообщения из
  SavedVariables повторяются один раз при входе. Черновики сами не отправляются.
- Очередь переживает закрытие игры и сбои сети. Отправка повторяется при старте
  расширения и каждые 5 минут, а запись удаляется только после ответа backend
  `ok: true`. Повторения используют исходный ID, backend их не дублирует.
- Статус в игровом окне означает завершение передачи маркеров. Прямого подтверждения
  записи на сервер в WoW 3.3.5 этот транспорт не возвращает.

## Backend

`POST /api/v1/contact`: `id`, `token`, `message_id` (16 hex), `category`
(`error`, `suggestion`, `other`), `body`, `client`, `addon_version`,
`extension_version`. Авторизация использует отдельный анонимный токен явных
действий пользователя из `/api/v1/quest-voters`, общий с оценками квестов.
При включённых метриках сохраняются персонаж, GUID и игровой сервер из снимка
на момент отправки. При выключенных метриках или запрете передачи персонажа
обращение анонимное. Разрешение проверяется при получении первых частей,
сборке и перед HTTP-доставкой. Включение метрик позже не раскрывает ранее
анонимное обращение, смена героя не меняет автора отложенного сообщения.

Приватная таблица `contact_messages`: один экземпляр `(sender_id,message_id)`,
категория, текст, версии и время. При включённой диагностике дополнительно
сохраняются `diagnostics_attached`, `addon_diagnostics` и `extension_diagnostics`;
логи не смешиваются с текстом обращения. Изменение текста с тем же ID отклоняется.
Поля `submitted_at` и `created_at` разделяют время нажатия в клиенте и время
приёма на сервере; `character_name`, `character_realm`, `character_guid`
пусты для анонимных обращений. Старые записи автоматически не атрибутируются.
Лимит — 20 новых сообщений от установки в час и 60 запросов от IP в час.
Открытого API чтения сообщений нет. Для команды обращения доступны в серверной
SQLite, например:

```sql
SELECT datetime(created_at, 'unixepoch') AS received_utc,
       datetime(submitted_at, 'unixepoch') AS submitted_utc,
       character_name, character_realm, category, body,
       client_version, addon_version, extension_version
FROM contact_messages ORDER BY created_at DESC LIMIT 50;
```
